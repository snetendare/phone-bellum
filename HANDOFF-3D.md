# Handoff: getting the 3D board into the live game

Repo `snetendare/phone-bellum`, branch `refactor/render-split`. `main` (with the factions game mode) is merged in. Not merged into `main`, no PR yet.

## Where things stand

- **2D board split out.** `src/render2d.js` draws the board and reads the game only through `view()`. Shared art (palette, coats of arms, tower icons) is in `src/art.js`. `node tools/tests/snapshots.js before` / `after before` checks the 2D drawing hasn't changed (68 fixed board moments, all identical so far).
- **3D board.** `src/render3d.js` (three.js 0.180.0 in `vendor/`) has the same calls and the same `view()` as `render2d.js`. `src/camera3d.js` has three views: strategic (straight down), angled and ground (ground is for watching only). `src/models3d.js` holds low-poly models, picked from unit stats. The six tier 4 units have their own models, picked by name (Ether Golem, Sun Priest, Meteor Caller, War Mammoth, Necromancer, Truespear).
- **3D test page** `lab3d.html` (`src/lab3d.js`, `src/lab3d-template.html`). You deploy blue against the AI, with unlimited gold. Pick a unit and tap a tile, tap a new squad to take it back, drag to move it. This works in the strategic view and in the angled view. The Strategic / Angled / Ground buttons switch views. Auto lets the AI deploy. Blue: AI watches two AIs.
- **Camera input.** In the strategic view, and in the angled view while `opts.placing()` is true, the page can take taps, one-finger drags (`onPress` / `onDrag` / `onDrop`) and mouse hover. `render3d.js` hands these on as tiles.
- **Artifact.** "No Mans Land · 3D test", https://claude.ai/artifact/S5EmsCVWqpqm3BfkWUQ5w8. To update it: `node src/build.js && node tools/build-artifact.js`, then publish `lab3d-artifact.html` to that URL. `vendor/` and `icon.png` are already published there.
- **Checks.** `tools/tests/deploy3d.js`: deploy in both views, then fight and round 2. Serve the site on port 8766, `cd tools && npm i`, and run with `NODE_PATH=tools/node_modules` from a scratch folder (it writes screenshots). Headless Chromium needs `--use-gl=angle --use-angle=swiftshader` and runs at about 10–15 fps. That speed is software rendering and doesn't predict phone performance.
- The live game (`index.html`, `src/site-template.html`) still uses the 2D board only.

## Before the 3D board goes into the live game

Ship it as an opt-in setting first. Keep the 2D board as the default until 3D has held up in real matches.

1. **Merge `main` into the branch first.** Done. `main`'s factions game mode (`deb5f15`) is merged in. The only drawing change on `main` (looking up tower types with `Game.towerTypeById`, so faction towers are found) is now in `src/art.js`. Checks after the merge: the snapshot check run on `main` and on the merged branch gives 71 identical moments, `tools/tests/factions.js` passes and so does `tools/tests/deploy3d.js`. Faction towers still need 3D models; for now they use the plain keep. `src/factions.json` is still empty, so the Factions mode can't be played in the live game yet.
2. **Wire the game's board input to the 3D board.** Done. The game's board input (`src/site-template.html`, "board input") is now five functions on tiles: `boardPress`, `boardDrag`, `boardDrop`, `boardHover` and `boardTap`. The 2D canvas's pointer handlers and `render3d.js`'s `onPress` / `onDrag` / `onDrop` / `onHover` / `onTap` both call them, so there is one set of rules. With `?board=3d` in the address, the game loads three.js from `vendor/` and the 3D code from `src/` and puts the 3D board in place of the canvas. While deploying, the angled view takes taps and drags too. If loading fails, it stays on 2D. This is for trying 3D out, not the setting from step 4, and the single-page artifact can't load it (step 6). The 3D board redraws every frame (step 3). It has no view buttons yet: pinch or scroll to change views. Also fixed: the 3D floor stayed black when the board started before a match existed. `tools/tests/game3d.js` checks dragging, placing and taking back, the tower, unit and enemy sheets, Move (tap, undo, drag) and placing in the angled view. The 2D snapshots are still identical to `main`, and the 2D UI tests still pass. `pack-ui.js` already failed before this change, and `move-ui.js` fails now and then when a random package squad lands on its fixed target tile.
3. **Test on real phones (the most important step).** The code half is done. Testing on phones is still to do.
   - **Idle.** The 3D board now draws only during fights, while the camera moves on its own, and for 0.7 s after a change or a touch. In the shop it sits at 0 frames per second. The battery and heat test still has to show whether that's enough.
   - **Meter.** Top right of the 3D board: frames drawn in the last second, the slowest frame, quality and pixels per CSS pixel. During a fight it adds live bodies and draw calls. After a fight it shows that fight's average frame rate, its slowest second and the most bodies at once (also logged to the console). Tap it to step the quality: high (up to 2 pixels per CSS pixel, shadows), medium (1.5, shadows), low (1, no shadows). The choice is remembered on the phone.
   - **Where to test.** Artifact "No Mans Land 3D Game", https://claude.ai/artifact/5ZUYFDjVS6eSv234RBHHEy: the full game, starting on the 3D board, with two-player matches through PeerJS. "Play vs Claude" doesn't work there. To update it: `node src/build.js && node tools/build-artifact.js`, then publish `game3d-artifact.html` to that URL. `vendor/` is already published there. The site itself works too, with `?board=3d`.
   - **What to measure.** On a mid-range Android and an older iPhone: the "last fight" line for big late-game fights (round 8 and later) at each quality, the slowest frame while dragging squads and moving the camera, and battery drain and heat over 15 minutes of play. Note what the meter says when the phone feels slow.
   - **Touch, measured headless at 390×844.** In the angled view, your zone shows only 6 of 12 columns at the back rows and 8 at the front row. The bottom fifth of the board is empty ground in front of the board. Tiles there are about 35 px (back) to 63 px (front); the 2D board's tiles are about 30 px. Outer columns need a drag on empty ground to reach. Fixing it means choosing between pulling the camera back (smaller tiles), tilting it steeper, or moving it toward your zone. Decide after trying it on a phone. Also check that dragging a new squad isn't mistaken for moving the camera.
   - `tools/tests/game3d.js` now also checks that the board idles in the shop, the quality steps and the fight summary.
4. **Fall back to 2D when 3D can't run.** If WebGL is missing or crashes, or the phone is too slow, switch to the 2D board on its own. Add a 2D / 3D switch in settings.
5. **Check that two-player matches stay safe.** The renderer only draws, and the battle engine is untouched, so fights still match on both phones. Test one phone on 2D and the other on 3D, rejoining a match, and the countdown. Add a check that 3D never shows what 2D hides from the opponent: hidden enemy squads, stealth units, tower types and characters before they're revealed.
6. **Loading three.js** (about 720 KB). The live site serves it from `vendor/`. The game artifact is a single inlined page (`tools/build-artifact.js`), so it needs three.js from a CDN (pinned to 0.180.0) or the files published next to it. Load it only when 3D is on, so the 2D game opens as fast as before.
7. **Tests.** The existing Playwright tests tap the 2D board by grid position. Keeping 2D as the default keeps them valid. Add 3D versions of the key flows (deploy, move, sheets, a full round in a two-player match), building on `deploy3d.js`.
8. **Smaller gaps.** Models for units that still use the general figures, if wanted. Fix the Counter Lab artifact build: `tools/build-artifact.js` stops at the Counter Lab step because its check rejects any page that mentions "Load units", and Counter Lab help text now does. Decide what the start screen and map picker look like in 3D (the map thumbnails can stay 2D).

Steps 1 and 2 are code work that can start now. Step 3 needs the owner testing on their phones, and its results decide how far to take 3D as the default.
